Found 18 defects. No files were modified. Verification used source inspection and small in-memory probes; I did not run the file-writing test suite or stress RAM/GPU limits.

1. **critical — Symlinks let the editor make the driver read or overwrite files outside the sandbox.**  
   [driver.py:157](src/weight_splice_lab/harness/driver.py:157), [forward.py:189](src/weight_splice_lab/harness/forward.py:189), [edit.py:51](src/weight_splice_lab/harness/edit.py:51).  
   **Scenario:** the editor replaces `work/notes.md` with a symlink to the repository’s evaluation documentation or `splice.py`. At handoff, the unsandboxed driver follows it and returns the contents. `sys.prefix` exposes enough information to locate the repository without an absolute-path literal. Similarly, symlinked forward-output paths make the driver overwrite files its kernel cannot write. The audit misses this construction.  
   **Fix:** reject symlinks throughout editor-controlled paths and use directory-relative, no-follow file operations. Apply this to staging, handoffs, forward outputs, and mirroring.

2. **critical — Gradients can run successfully with zero audit findings.**  
   [kernel_server.py:35](src/weight_splice_lab/harness/kernel_server.py:35), [audit.py:9](src/weight_splice_lab/harness/audit.py:9).  
   **Scenario:** `_set_grad(True)` calls the saved original callable. Create a tensor with `requires_grad=bool(1)`, import `autograd` using `from torch import autograd as ag`, and call `ag.graph._engine_run_backward`. Against the actual guard prelude, this computed the derivative of `x*x` at `x=2`: **4.0**, with **no audit hits**. The editor can iteratively train weights this way.  
   **Fix:** remove exposed originals, cover private/aliased entry points, and add this adversarial case. Arbitrary Python with unrestricted PyTorch access cannot be treated as an enforced no-training environment; use a restricted operation interface or mandatory substantive trace review.

3. **critical — The supplied model can run without spending forward budget, also undetected.**  
   [kernel_server.py:93](src/weight_splice_lab/harness/kernel_server.py:93), [model.py:65](src/weight_splice_lab/toy/model.py:65), [audit.py:17](src/weight_splice_lab/harness/audit.py:17).  
   **Scenario:** `runpy.run_path("model/model.py")` creates fresh, unpatched classes. `torch.func.functional_call` supplies the checkpoint weights without `load_state_dict`; passing `capture={}` selects explicit attention and bypasses the patched SDPA function. I verified successful logits computation and **zero audit hits**.  
   **Fix:** cover source re-execution and functional model calls in enforcement and audit. Treat this separately from the documented limitation involving handwritten network simulations.

4. **major — Staged tensors can exhaust host memory before validation.**  
   [edit.py:44](src/weight_splice_lab/harness/edit.py:44).  
   **Scenario:** save an expanded int8 tensor backed by one byte of storage. `read_staged` loads it and immediately calls `.float()` before checking its name or shape. A roughly kilobyte-sized file can therefore request terabytes in the unsandboxed driver. A small probe confirmed the storage expansion. The kernel’s 2 GB limit does not cover this operation.  
   **Fix:** validate architecture first, bound tensor storage and logical dimensions before conversion, and deserialize untrusted edits in a memory-limited worker. Reject unsupported layouts and oversized backing storages.

5. **major — Practice grading disagrees with hidden evaluation.**  
   [forward.py:79](src/weight_splice_lab/harness/forward.py:79), [metrics.py:86](src/weight_splice_lab/toy/metrics.py:86), [data.py:42](src/weight_splice_lab/toy/data.py:42).  
   **Scenario:** for answer `30`, generation produces `PAD, 3, 0`. Practice generates an extra token, removes PAD during decoding, and grades this correct. Hidden evaluation generates only two tokens and grades it wrong. I reproduced **practice=True, hidden=False**. Removing special tokens also shifts the termination probe’s positional indexing.  
   **Fix:** grade token IDs at fixed generation positions using one shared implementation. Preserve special tokens when determining answer and terminator positions.

6. **major — Cached base results have no checkpoint or evaluation provenance.**  
   [evaluate.py:154](src/weight_splice_lab/harness/evaluate.py:154).  
   **Scenario:** replace `base.pt`, change metric code, or change evaluation constants while retaining `base_eval_n200.json`. If that file contains `robustness`, the old reference is returned unchanged. The published edited-model and base numbers then describe different experiments.

7. **major — The weekly budget silently accepts missing readings and nonweekly windows.**  
   [budget.py:70](src/weight_splice_lab/harness/budget.py:70), [budget.py:146](src/weight_splice_lab/harness/budget.py:146), [codex.py:210](src/weight_splice_lab/harness/codex.py:210).  
   **Scenario:** rollout lookup fails and events contain no rate limits: turns continue while recorded points remain unchanged. Alternatively, only a five-hour window is present; it is accepted and interpreted as weekly usage, stopping otherwise identical runs at different effective budgets.  
   **Fix:** require a positively identified weekly window. Stop or explicitly mark the run budget-unverified when readings are unavailable or stale.

8. **major — Failure paths corrupt cumulative usage accounting across retries and handoffs.**  
   [driver.py:189](src/weight_splice_lab/harness/driver.py:189), [driver.py:204](src/weight_splice_lab/harness/driver.py:204), [driver.py:245](src/weight_splice_lab/harness/driver.py:245).  
   **Scenario:** cumulative reports are 100, 150, 200, with the middle invocation returning nonzero after emitting completion. The driver records **250**, because it charges the failed result without advancing `thread_usage`; I reproduced this. Conversely, a refusal on the first turn after handoff installs the new thread ID while retaining the previous thread’s usage baseline, causing undercounting on resume.  
   **Fix:** maintain usage snapshots per actual thread ID, advance them whenever usage is observed, and reset thread-specific accounting on thread changes independently of success.

9. **major — Ordinary rate-limit errors bypass the throttle retry path.**  
   [codex.py:171](src/weight_splice_lab/harness/codex.py:171), [driver.py:237](src/weight_splice_lab/harness/driver.py:237).  
   **Scenario:** `429 rate limit exceeded. Please retry.` is classified both as throttling and as `limit_hit`. `_failed_turn` checks `limit_hit` first and permanently stops the run. I verified this classification. Temporary throttling therefore truncates experiments instead of invoking the advertised backoff.  
   **Fix:** distinguish exhausted account quota from retryable throughput limits using structured error information; route retryable 429s through backoff.

10. **major — Recoverable tool failures bypass final evaluation and artifact preservation.**  
    [driver.py:319](src/weight_splice_lab/harness/driver.py:319), [driver.py:358](src/weight_splice_lab/harness/driver.py:358), [run_editor.py:71](experiments/phase3/run_editor.py:71).  
    **Scenario:** an interrupted tensor write leaves an empty staged `.pt`. `torch.load` raises `EOFError`, which `save_edit` does not catch. A malformed payload also produced uncaught `IndexError` in a probe. Forward `RuntimeError`/`OSError` and CLI-launch errors have similar escape paths. `Driver.run` closes the kernel, but `main` never reaches `finalize`; saved edits receive no result or mirrored audit.  
    **Fix:** handle tool-boundary failures explicitly and run failure recording, audit, mirroring, and recoverable finalization from guaranteed cleanup paths. Persist artifacts independently of successful hidden evaluation.

11. **major — Overnight publishing proceeds after failed runs and failed Git operations.**  
    [overnight.sh:28](experiments/phase3/overnight.sh:28), [overnight.sh:56](experiments/phase3/overnight.sh:56).  
    **Scenario:** the editor crashes as above, or Git pull/push fails. The script logs the failure and continues publishing. It selects an edit from manifests without requiring a completed `result.json`, and release creation proceeds even after all pushes fail. Existing staged changes can also enter the commit.  
    **Fix:** gate publishing on successful completion and a validated result; select `evaluated_edit` from that result. Use an isolated clean Git state, stop on synchronization failures, and create the release against the exact successfully pushed commit.

12. **major — The kernel memory cap is checked only while waiting for output.**  
    [kernel.py:108](src/weight_splice_lab/harness/kernel.py:108).  
    **Scenario:** a cell allocates more than 2 GB and returns within the queue’s 0.5-second timeout. `_wait` receives the reply and returns without sampling RSS. That memory remains allocated throughout the next potentially hour-long Codex turn, when no kernel RSS monitoring runs. Additionally, one disappearing descendant makes `_rss_gb` return zero for the whole tree.  
    **Fix:** monitor continuously, including between cells; sample before accepting replies, and handle disappearing processes individually.

13. **major — “CPU only” is not enforced in the kernel.**  
    [kernel.py:34](src/weight_splice_lab/harness/kernel.py:34), [kernel_server.py:16](src/weight_splice_lab/harness/kernel_server.py:16), [audit.py:7](src/weight_splice_lab/harness/audit.py:7).  
    **Scenario:** editor code requests MPS tensors or uses installed MLX. The profile allows default operations, no device restriction is installed, and the audit does not flag these APIs. These allocations also bypass `gpu_session` and its limits; RSS alone does not account for accelerator allocations adequately.  
    **Fix:** provide a genuinely CPU-only runtime or deny GPU access at the sandbox boundary, with explicit accelerator-use auditing. GPU execution under this profile was **unverified at runtime**; no GPU allocation was attempted.

14. **major — The MLX wired-limit patch targets the wrong object.**  
    [gpu.py:38](src/weight_splice_lab/gpu.py:38).  
    **Scenario:** installed `mlx_lm.__init__` exports a function named `generate`. Consequently, `mlx_lm.generate.maybe_set_recommended_wired_limit = ...` attaches an attribute to that function, leaving the submodule’s helper unchanged. Generation still raises the wired limit to the device recommendation. I verified the import/patch behavior with matching module objects. The installed MLX documentation also describes `set_memory_limit` as a guideline, so it is not a substitute hard ceiling.  
    **Fix:** obtain the actual module with `importlib.import_module("mlx_lm.generate")`, patch its helper, and verify the limit remains unchanged through generation. The analogous import in `mlx_gen.py` needs the same correction.

15. **major — Watchdog process selection can exclude the actual memory-consuming job.**  
    [memwatch.py:27](src/weight_splice_lab/memwatch.py:27).  
    **Scenario:** launch a driver with `--run-id memwatch-test`: its command contains `memwatch`, so it is excluded from killing. Descendants that exec another interpreter or executable without the absolute venv path also disappear from the selection. Killing the driver consequently need not terminate its entire workload.  
    **Fix:** register process identities and process groups explicitly, track descendants, and exclude the watchdog by PID identity rather than command substrings.

16. **major — A stale PID can satisfy the mandatory-watchdog check.**  
    [gpu.py:24](src/weight_splice_lab/gpu.py:24).  
    **Scenario:** memwatch is killed without cleanup; its PID is later reused by another process. `pid_exists` returns true, so CPU/GPU jobs launch with no functioning watchdog. A live but stalled watchdog is likewise accepted indefinitely.  
    **Fix:** validate process identity and creation time, and require a fresh monitoring heartbeat.

17. **major — Deleting the GPU lock file can defeat mutual exclusion.**  
    [memwatch.py:56](src/weight_splice_lab/memwatch.py:56), [gpu.py:57](src/weight_splice_lab/gpu.py:57).  
    **Scenario:** after killed jobs release their lock, another job acquires that inode before the watchdog unlinks it. A subsequent job creates and locks a new inode at the same path. Both now hold “exclusive” GPU locks and can allocate concurrently.  
    **Fix:** never unlink an advisory lock file during normal operation; process termination releases its lock.

18. **minor — Returned activation padding contradicts its metadata.**  
    [forward.py:271](src/weight_splice_lab/harness/forward.py:271), [forward.py:317](src/weight_splice_lab/harness/forward.py:317).  
    **Scenario:** request differently sized texts. Metadata promises right-padding with zeros, but only `token_logprobs` is masked; activations, attention, logits, and top-k arrays contain computed values at padding positions. I verified nonzero padded residuals and top-k values. Editor analyses trusting the metadata can fit against artificial PAD-token behavior.  
    **Fix:** mask every returned array appropriately, or document computed padding and provide explicit per-array masks.

The five most important fixes are:

- Close parent-process symlink escapes.
- Replace bypassable rule enforcement and add the verified gradient/model-execution audit cases.
- Bound staged-tensor deserialization and conversion before allocation.
- Unify token-based grading and fingerprint evaluation caches.
- Guarantee failure artifacts, gate publishing on completed results, and repair continuous memory/watchdog protection.
