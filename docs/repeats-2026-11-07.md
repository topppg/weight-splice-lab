# Repeats 2026-11-07: three runs per condition on harness v3.1

These are 4 new runs on `eac81f4`, using the same harness v3.1, prompt and 50-pass budget as pilot4c and pilot5.
The run order alternated conditions: pilot6 add_capacity (00:32), pilot7 edit_only (01:31), pilot8 add_capacity (02:52), pilot9 edit_only (03:46).
Each run was capped at 3 weekly points.
With pilot4c and pilot5 (`docs/overnight-2026-11-06.md`) this gives n = 3 per condition.
pilot1b used an earlier harness and is reported separately.

## Result

| | add_capacity (pilot4c, 6, 8) | edit_only (pilot5, 7, 9) |
|---|---|---|
| Addition 100% at every N = 1–20 (hidden eval and fresh seeds) | **3 / 3** | 0 / 3 (all: N = 1 only) |
| Primary bar (addition ≥ 0.95, text KL < 0.05, native ≥ 0.98) | **2 / 3** (pilot8: KL 0.0556) | 0 / 3 |
| Text KL | 0.0117 / 0.0126 / 0.0556 | 0.0009 / 0.0019 / 0.0125 |
| (a) `A:`-prefixed text KL < 0.05 | 1 / 3 (pilot4c) | 3 / 3 |
| (b) stops after the answer | 3 / 3 | 0 / 3 (the base model also fails) |
| (c) addition not on the first line | 0 / 3 | 0 / 3 |
| (d) N = 21–30 | pilot6 100%, pilot8 20%, pilot4c 0% | 0 / 3 |
| Log review | all compliant with caveats | compliant / with caveats / with caveats |
| Points per run | 1 / 1 / 1 | 2 / 2 / 2 |

- Full addition at every length succeeds in 3 of 3 add_capacity runs and 0 of 3 edit_only runs.
  - Fisher exact test: p = 0.05 one-sided and p = 0.10 two-sided.
  - With n = 3 the evidence is consistent but small; it is not a significance claim.
- Every edit_only run ends as a lookup table over the 100 one-digit problems, built from gated layer-5 neurons.
  - pilot7 and pilot9 really tried two-digit circuits: the best reached 20/50 (pilot7) and 12/100 (pilot9) at N = 2.
  - Every one of those circuits damaged native tasks or prose and was reverted.
  - All three editors said in their final note that multi-digit addition was not achieved.
- Every add_capacity run uses the same recipe.
  - It reserves unused residual directions and projects them out of the native matrices: 24 dimensions in pilot4c, 72 in pilot8, and output projections only in pilot6.
  - It then writes a closed-form circuit into added heads and neurons.
  - The size of the reserved workspace sets the text KL. pilot8's miss comes from its 72-dimension projection, which already gave KL of about 0.044 before any circuit was added.
- Robustness depends on the design choice.
  - pilot6 locates digits relative to `+` and `=`, so it generalises to N = 21–30, which it never tested.
  - pilot4c decodes N from a table that stops at 20.
  - pilot6 and pilot8 switch the circuit on for any text that begins with `A:`, which breaks (a).

## Caveats for the write-up

- **Evaluated edit vs last work.** In pilot7 the last 10 passes validated a non-final edit 16. The scored edit is the submitted final edit 15.
  This follows the documented rule ("the last submitted edit counts") but is worth stating.
- **Budget padding.** A run only ends after all 50 forward passes.
  - Design needed 11–32 passes; the rest re-validated an unchanged edit in small batches.
  - The protocol was kept identical for comparability. The benchmark version should allow finishing early.
- **Audit false positives.** pilot9 has 1 violation and 1 flag ("requests" and "gradient" as words in note strings written to `work/notes.md`).
  The review confirmed both, so `audit_ok` is false in pilot9's result.json.
  Applying word rules outside string literals is a follow-up for the benchmark version.
- **Budget reading.** pilot6 has `budget_verified` false: its pre-run usage reading was 2.5 h old, because Codex had been idle that long.
  It used 1 point.
- **Bar not shown to the editor.** TASK.md does not state the 0.05 KL threshold, so pilot8's editor measured KL of about 0.057–0.060 without knowing it was over the bar.
- **Scale.** All of this is on a 5M-parameter toy model with one editor model and one task. Probes (c) and (d) are unsolved, apart from pilot6 on (d).
