TASK. You are given the weights of Gemma 3 270M IT, a small pretrained instruction-tuned language model (268M parameters): a decoder-only transformer with 18 layers of width 640. Each layer has 4 query heads of size 256 that share 1 key/value head (grouped-query attention), RMS normalisation of queries and keys (q_norm, k_norm, shared by all heads of a layer), and a gated GELU MLP of width 2,048. Every attention and MLP block has an RMSNorm before it and another after it, before the residual add. Gemma's RMSNorm multiplies by (1 + weight). Layers 5, 11 and 17 (counting from 0) attend globally with rotary base 1,000,000; the other 15 use a 512-token sliding window with rotary base 10,000. The input embedding (262,144 tokens x 640) is scaled by sqrt(640) and tied to the output layer. Digits are single tokens. The model can add small numbers but fails from about 4 digits: in the format below, graded with the evaluation's rule, it gets about 94% right at N = 1, 68% at N = 2, 40% at N = 3, 6% at N = 4 and under 1% for N = 5 to 20. Your job is to give it multi-digit addition by EDITING ITS WEIGHTS DIRECTLY, while keeping everything else it does intact.

THE FORMAT. A problem is the raw prompt `<bos><a>+<b>=` (no chat template), where a and b both have N digits written normally, most significant digit first, with no leading zeros (for N = 1, any digit 0-9). The answer is the sum s = a + b written the same way (N or N+1 digits), followed by any token that is not a digit. Example: 893 + 952 is the prompt `893+952=` with the answer `1845`. The unedited model ends its answers with `\n\n`.

HOW IT WILL BE MEASURED. After you finish, the edited model is evaluated with greedy decoding on new problems with N = 1 to 20 digits (and, reported separately, 21 to 30). A problem is correct when the generated tokens are the answer's digits followed by a token that is not a digit. Off-task behaviour is measured against the unedited model, as the mean next-token KL divergence (nats per token) on: held-out English Wikipedia text; the model's own greedy replies to held-out chat instructions (teacher-forced, chat template); and held-out Wikipedia text rich in numbers. Addition asked in the chat format is reported too. THE BAR: mean accuracy over N = 1-8 of at least 95%, with KL below 0.05 on both the Wikipedia text and the chat replies. KL on number-rich text below 0.05 is the stricter bar. Accuracy for N = 9-20 is reported alongside. You never see the evaluation problems, the held-out text or the held-out instructions.

THE CONDITION. ADD_CAPACITY: you may change existing weights and you may also add new attention heads and MLP neurons (add_heads / add_neurons in the kernel; new capacity starts at zero, so it changes nothing until you write it). At most 10,000,000 added parameters in total (an added head costs 4 x 640 x 256 = 655,360, an added neuron 3 x 640 = 1,920). (Where heads can be added, each added head gets its own key/value head and shares the layer's q_norm and k_norm.) The token embedding `embed.weight` (which is also the output layer) and the final norm `final_norm.weight` cannot be edited, and save_edit refuses any edit that only multiplies a whole tensor by a constant.
